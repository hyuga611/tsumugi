# arch — クレート分割・依存選定・マイルストーン

対象: Windows / macOS / Linux。実装言語 Rust（手元は 1.97.1）。
ライセンスは Rust 慣例に合わせ MIT OR Apache-2.0。

---

## 1. クレート分割

```
tsumugi/
├─ crates/
│  ├─ tsg-pty       PTY 抽象（ConPTY / Unix PTY）。プロセス起動と生バイト
│  ├─ tsg-term      エスケープ解析 -> グリッド。スクロールバック。OSC 133 セマンティックマーク
│  ├─ tsg-buffer    Buffer トレイト。Term バッファと File バッファを同じ座標系に載せる
│  ├─ tsg-modal     🔴 中核。モード機械・コマンドレジストリ・モーション・オブジェクト・
│  │                オペレータ・キーマップ解決・Dispatcher。I/O 依存ゼロ
│  ├─ tsg-mux       セッション / タブ / ペインの木。サーバプロセス。IPC
│  ├─ tsg-render    wgpu。グリフアトラス。ダメージ追跡
│  ├─ tsg-ui        winit ウィンドウ。入力イベント -> Command。ステータス行・ガター・
│  │                メニュー・パレット。IME
│  ├─ tsg-config    TOML 設定、キーマップ上書き、テーマ、ホットリロード
│  └─ tsg           バイナリ。クライアント / サーバ両モードのエントリ
└─ docs/
```

### 依存の向き（一方向を厳守）

```
tsg ──> tsg-ui ──> tsg-render ─┐
 │        │                    ├──> tsg-buffer ──> tsg-term ──> tsg-pty
 │        └──> tsg-modal ──────┘
 └──> tsg-mux ──> tsg-buffer
          └──> tsg-config
```

**`tsg-modal` から `tsg-render` / `tsg-ui` / `tsg-pty` への依存は禁止。**
このルールを破った瞬間、モーダルエンジンのヘッドレステストが書けなくなり、
仕様（`modal-spec.md`）の回帰検証が不可能になる。CI で `cargo deny` 相当の依存チェックを入れる。

## 2. 各クレートの責務

### tsg-pty
子プロセスの起動、PTY のリサイズ、生バイトの読み書き、終了検知。
**ConPTY を自作しない。**

### tsg-term
バイト列 -> エスケープシーケンス解析 -> セルグリッドへの適用。
持つもの: セル（文字・前景/背景・属性・幅クラス）、スクロールバックのリングバッファ、
代替画面、**セマンティックマーク**（OSC 133 の A/B/C/D = プロンプト開始 / コマンド開始 /
出力開始 / コマンド終了＋終了コード）、cwd 追跡（OSC 7）、ハイパーリンク（OSC 8）。

セマンティックマークは `modal-spec.md` の `[[` `]]` `[e` `]e` `ic` `ac` `io` `ao` と、
`mouse-parity.md` の左ガターの**唯一の情報源**。ここが弱いと製品の売りが全部死ぬ。

### tsg-buffer
`Buffer` トレイト。**この抽象が「エディタ内蔵」を実質タダにする。**

```rust
pub trait Buffer {
    fn line(&self, n: usize) -> Option<Cow<'_, str>>;
    fn line_count(&self) -> usize;
    fn kind(&self) -> BufferKind;              // Term(Primary) | Term(Alt) | File
    fn allows(&self, op: OperatorId) -> bool;  // modal-spec §7 の可否表
    fn edit(&mut self, range: Range, text: &str) -> Result<EditId>;
    fn undo(&mut self) -> Option<EditId>;
    fn marks(&self) -> &SemanticMarks;         // File では空
}
```

`tsg-modal` のモーション・テキストオブジェクトは、このトレイトの上にだけ書く。
Term 用と File 用を二重実装しない。**これを守れば、内蔵エディタは
「File バッファを `Buffer` として繋ぐ」だけで完成する。**

### tsg-modal（中核）
純粋な状態機械。入力は `InputEvent`（キー、あるいは UI が翻訳したマウス由来のもの）、
出力は `Command` の列と状態遷移。`CommandRegistry` がすべてのコマンドのメタデータ
（ID、既定キーマップ、マウス経路、メニューセクション、説明文）を保持し、
`mouse-parity.md` §2.2 のパリティテストと、右クリックメニュー・コマンドパレットの
生成元になる。

### tsg-mux
セッション（永続）> タブ > ペインの木。ペインは PTY か File バッファを持つ。
サーバプロセスとして常駐し、クライアントからの接続を受ける。
IPC: Unix domain socket / Windows named pipe（`interprocess` クレートで統一）。
プロトコルは JSON Lines。デバッグ可能・外部からスクリプト可能を優先し、
性能が問題になったら差し替える。形は [`rpc.md`](rpc.md) で公開している。

**このソケットが製品の信頼境界そのもの。** ここへ書けるプロセスはシェルへ
任意のキーを送れ（＝そのユーザとして任意コード実行）、読めるプロセスは画面に
出た全部を読める。したがって、既定の名前空間ソケットは使わない
（Linux の抽象名前空間はパーミッションを持たず、Windows の既定 DACL は
Everyone に読みを与える）。Unix は 0700 のディレクトリ配下のファイルソケット、
Windows は現在のユーザ SID だけを許す DACL。**閉じられなければ開かない。**
詳細は [`SECURITY.md`](../SECURITY.md)。

### tsg-render
wgpu。グリフアトラス（rustybuzz でシェーピング -> swash でラスタライズ -> アトラスに詰める）。
ダメージ矩形のみ再描画。60/120Hz。

シェーピングの結果は**送り幅ではなくクラスタで**受ける。端末は格子なので、
合字の字形が「入力の何文字ぶんか」を見て、その先頭のセルに置く（M8）。

### tsg-ui
winit。OS イベント -> `Command`。**IME はここが主戦場**（§6）。
ステータス行・左ガター・タブバー・ペインヘッダ・コンテキストメニュー・パレットの描画指示。

## 3. 依存クレート選定

| 用途 | 採用 | 理由 / 不採用にしたもの |
|---|---|---|
| PTY | **portable-pty** | WezTerm 本体が使っている実績。ConPTY / forkpty を一枚で吸収。自作は ConPTY の罠に数週間溶かすだけ |
| エスケープ解析 | **vte** | Alacritty の解析器。VT の状態機械だけを提供し、セル意味論は渡してくれる = こちらの設計自由度が残る。`termwiz` はセルモデルまで持ってきて設計を規定するため不採用 |
| ロープ | **ropey** | File バッファ。実績十分 |
| ウィンドウ / 入力 / IME | **winit** | 実質唯一の選択肢。IME API（Preedit / Commit / set_ime_cursor_area）を持つことが決め手 |
| GPU | **wgpu** | DX12 / Metal / Vulkan を一枚で。Windows 優先でも将来を潰さない |
| シェーピング | **rustybuzz** | HarfBuzz の Rust 移植。リガチャ・CJK に必須 |
| ラスタライズ | **swash** | ヒンティング・カラー絵文字対応。`cosmic-text` は段落レイアウトを前提としており、セル格子のターミナルとは噛み合わないため不採用（ただし工数が破綻したら退避先） |
| フォント探索 | **fontdb** | フォールバックチェーンを自前で組むため、低レベルなものを選ぶ |
| 文字幅 | **自前テーブル + unicode-width** | East Asian Ambiguous を設定で切り替える必要があり、`unicode-width` 単体では足りない（§6） |
| 書記素 | **unicode-segmentation** | 結合文字・ZWJ 絵文字の1セル判定 |
| IPC | **interprocess** | UDS と名前付きパイプを同一 API で |
| 設定 | **serde + toml** | |
| 設定ホットリロード | **notify** | |
| 正規表現 | **regex** | `:s` `:g` `/` |
| CLI | **clap** | |
| エラー | **thiserror**（ライブラリ） / **anyhow**（バイナリ） | |
| 構文強調 | **自前の 1 行字句解析**（`tsg-buffer::syntax`） | tree-sitter は入れなかった。欲しいのは構文木ではなく「目が滑らないこと」で、文法ごとの依存とパーサ木の維持が釣り合わない。行をまたぐ状態を持たない代わりに、編集のたびに下の行まで塗り直さずに済む |
| 非同期ランタイム | **不採用** | std スレッド + crossbeam チャネル。ターミナルは並行数が小さく寿命が長いワーカーの世界で、async の複雑さに見合わない。mux サーバもクライアント毎スレッドで足りる |
| Lua / スクリプト | **不採用（v1）** | `concept.md` の「捨てるもの」。RPC の口で代替 |

## 4. 4つの不変条件

破ると設計が崩れる。PR レビューのチェック項目にする。

1. **単一コマンドバス** — すべての入力フロントエンドは `Command` を発行するだけで、
   状態を直接触らない。マウス等価が構造的に保証される（`mouse-parity.md` §2）。
2. **`tsg-modal` は純粋** — I/O 依存ゼロ。ヘッドレスでキー列 -> 状態のゴールデンテストが書ける。
3. **グリッドは末尾を持つドキュメント** — スクロールバックと現在画面は連続した1つのアドレス空間。
   `Buffer` トレイトで File バッファと共通化する。
4. **mux は常に別プロセス** — ローカル1ウィンドウでも GUI は必ずクライアント。
   永続性を後付けにしない（WezTerm/tmux の歴史が示す教訓）。

不変条件 4 は**レイテンシと引き換え**である。ローカルでも全キー入力と全出力が IPC を通る。
M2 で実測し、`Insert` モードのキー入力 -> 画面反映が 8ms を超えるなら、
グリッド転送だけ共有メモリの高速経路を足す（プロトコルは変えない）。**ここは M2 の判定ゲート。**

→ **実測済み（[`m2-results.md`](m2-results.md)）: IPC 往復の中央値 0.055ms、p95 0.073ms。**
予算 8ms に対して 70 倍以上の余裕があり、**共有メモリの退避策は不要**と確定した。
回帰テストで 4ms を上限に固定してある。

## 5. プロセス構成とデータフロー

```
  ┌─────────────── tsg (client, GUI) ───────────────┐
  │  winit event loop ─> tsg-ui ─> Command          │
  │        ▲                          │             │
  │  tsg-render <── grid mirror       │             │
  └────────┼──────────────────────────┼─────────────┘
           │ damage diff              │ Command (JSON Lines)
           │                          ▼
  ┌────────┴──────────── tsg-mux (server, 常駐) ────────────┐
  │  Dispatcher (tsg-modal) ─> 状態変更                      │
  │  セッション木: Session > Tab > Pane                       │
  │  Pane ─┬─ tsg-pty ─(bytes)─> tsg-term ─> Grid            │
  │        └─ File buffer (ropey)                            │
  └──────────────────────────────────────────────────────────┘
```

### スレッド構成（サーバ側）

| スレッド | 役割 |
|---|---|
| PTY reader（ペイン毎） | ブロッキング read -> チャネルへ |
| State thread（1本） | 全状態の唯一の所有者。PTY バイトと Command を単一キューで処理し、ダメージを生成 |
| Client writer（接続毎） | ダメージ差分をクライアントへ送出。**合流させる**（16ms 以内の更新はまとめる） |

状態の所有者を1スレッドに固定するのは、モーダル操作と PTY 追記の競合を
ロックではなく**順序**で解くため。ロックを使うと `[[` の途中でグリッドが伸びる、
といったバグが再現困難な形で出る。

### 描画

クライアント側にグリッドのミラーを持ち、ダメージ矩形のみ再描画。
vsync 駆動。入力があってから次フレームまでに反映されることを保証する。

## 6. 日本語 / CJK / IME 対応 — 明示的な差別化点

既存の Rust 製ターミナル（Alacritty / WezTerm 含む）が最も弱い領域であり、
日本語話者が作る意味が最も出る領域。**後回しにせず M1 から設計に入れる。**

### 6.1 文字幅

- **East Asian Ambiguous**（`※` `→` `①` `Ⅰ` 罫線素片など）を 1 幅にするか 2 幅にするかは
  設定 `ambiguous_width = 1 | 2` で切り替える。既定は 2（日本語環境の慣習）。
  セッション途中の変更でグリッドが壊れないよう、再レイアウト経路を用意する。
- **異体字セレクタ（IVS, U+E0100–）**、**結合文字**、**ZWJ 絵文字**、**肌色修飾**は
  `unicode-segmentation` で書記素クラスタに束ね、1セル（または 2セル）として扱う。
  セル分割してしまうと、日本語のログでカーソル位置が恒常的にずれる。
- 幅の判定結果はテストコーパス（実際の `ls` 出力・絵文字混在・罫線表）で回帰検証する。

### 6.2 IME

- winit の `Ime::Enabled / Preedit / Commit / Disabled` を使う。
  変換中文字列（preedit）は**カーソル位置にインライン描画**し、
  `set_ime_cursor_area` で候補ウィンドウを正しい位置に出す。
- 🔴 **モードに応じて IME を自動で有効化 / 無効化する。**

  | モード | IME |
  |---|---|
  | Insert | 有効（直前の状態を復元） |
  | Command `:` / Search `/` | 有効 |
  | **Normal / Visual / Operator-pending / Layout** | **無効化** |

  Normal モードではキーはコマンドである。ここで IME が生きていると `dd` が「っd」になる。
  vim ユーザーが `im_control` やプラグインで何年も戦ってきた問題を、
  **モードを本体が知っている**この設計なら最初から正しく解ける。**これは強い売り。**
  モードを抜けるときの IME 状態は記憶し、Insert に戻ったら復元する。

- プラットフォーム別の実装差（Windows TSF / macOS NSTextInputClient / Linux ibus・fcitx）は
  winit に寄せるが、**M0 のスパイクで3 OS すべての preedit 表示を実際に確認する**。
  ここが動かないなら winit を疑うより先に設計を見直す必要がある。

## 7. Windows / ConPTY の注意

- ConPTY は自分でエスケープシーケンスを再生成するため、子プロセスの出力がそのまま素通りしない。
  **OSC 133 が通るかは M0 で必ず実測する**（通らないなら製品の中核語彙が成立しないため、
  設計判断のやり直しが必要 = 最優先のスパイク）。
- 古い Windows の ConPTY にはリサイズ時の欠落等の既知問題がある。
  WezTerm と同様に**新しい `OpenConsole.exe` を同梱**して使うのが実務上の回避策。
- シェル統合（OSC 133 を出す設定）は PowerShell / bash / zsh / fish / nu 向けに
  こちらから配布する（`shell-integration/` に置き、`tsg --install-shell-integration` で導入）。
  **実装済み。** スクリプトはバイナリへ埋め込む（exe を 1 つ置いただけの環境で
  最初の 1 回を走らせたいため）。`tsumugi.ps1` だけはコメントも ASCII に保つ
  （PowerShell 5.1 が BOM 無しの .ps1 を ANSI として読むため）。
- パス表現（`C:\` と `/c/`）の差は `if` / `af` テキストオブジェクトの判定に効く。
  プラットフォーム別のパス認識器を持つ。

## 8. テスト戦略

| 層 | 手法 |
|---|---|
| `tsg-modal` | **ゴールデンテスト**。キー列を与え、モード・カーソル・レジスタ・バッファ内容を assert。`modal-spec.md` の表を機械的にテストへ落とす |
| `tsg-modal` | **パリティテスト**（`mouse-parity.md` §2.2）。CI で落とす |
| `tsg-term` | 実出力コーパスのリプレイ。`cargo build` のエラー出力、`docker logs`、`vttest` / `esctest`、CJK・絵文字混在。グリッドをスナップショット比較 |
| 文字幅 | ambiguous / IVS / ZWJ の専用ケース |
| `tsg-mux` | ヘッドレスクライアントでソケット越しに駆動。デタッチ -> 再アタッチで状態が一致すること |
| 統合 | 起動 -> コマンド実行 -> `]e` でエラーへ -> `!if` -> 実行、を通しで |

| **M8** | 仕上げ。リガチャ、テーマ、設定ホットリロード、RPC の口の公開 | **実装済み**。合字は rustybuzz のクラスタを「何セル目か」へ翻訳して格子に載せる。テーマは「素」の色 20 個から飾りを導く。設定は保存した瞬間に効く。外から動かす口を [`rpc.md`](rpc.md) として公開した。あわせて **mux ソケットを自分だけに閉じた**（それまで同じマシンの他ユーザから到達できた）。詳細は [`m8-results.md`](m8-results.md) |
| **M9** | 行き止まりを塞ぐ。一覧のスクロール、帰り道、設定の雛形 | **実装済み**。一覧（パレット / セッション / メニュー / 使い方）は入り切らない分を切り捨てず `scroll_into_view` を通す。ファイルを開いているあいだはステータス行に `✕ 端末へ戻る` を出す。設定ファイルは無ければ雛形ごと作る。詳細は [`m9-results.md`](m9-results.md) |

**M0 は他のすべてに優先する。** ここで潰れる仮定が3つ（ConPTY の OSC 133、3 OS の IME、
wgpu のフォント品質）あり、どれも「後で何とかなる」種類のものではない。

## 10. リスク

| リスク | 影響 | 対処 |
|---|---|---|
| ConPTY が OSC 133 を落とす | ターミナル固有モーション・オブジェクト・ガターが全滅（＝製品の売りが消える） | M0 で実測。駄目ならヒューリスティック（プロンプト検出）に格下げし、Windows は劣化モードと明示 |
| IME が3 OS で揃わない | 日本語話者向けの主要な売りが崩れる | M0 で実測。winit の該当 issue を先に読む |
| mux 分離のレイテンシ | 「速い」という基本価値が損なわれる | M2 でゲート。共有メモリ経路を退避策に用意 |
| フォント品質が既存に劣る | 常用してもらえない | swash + rustybuzz で足りなければ cosmic-text へ退避 |
| 単純に規模が大きい | 完成しない | M0–M2 で「tmux + 素の端末」を置き換えられる状態を作り、そこから毎日使う。ドッグフーディングを M2 から始める |
| モーダル層とアプリのキー衝突 | 使い勝手が壊れる | alt-screen 所有権モデル（`concept.md`）＋ `:pin` ＋ 所有権の常時表示 |
| **mux ソケットに他ユーザから触れる** | シェルへ任意のキーを送られる（＝任意コード実行）／画面の全部を読まれる | M8 で実際に空いていた。Unix は 0700 のディレクトリ配下のファイルソケット、Windows は所有者だけの DACL ＋繋ぎ先の確認。**閉じられなければ開かない**（[`SECURITY.md`](../SECURITY.md)） |
| 子プロセスの出力でメモリが尽きる | 落ちる | スクロールバックに上限（M8）。OSC が持ち込む文字列も長さを切る |
