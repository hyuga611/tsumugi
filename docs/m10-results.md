# M10: AI エージェントと、読む形

## 0. きっかけ: TUI が軒並み崩れていた

Claude Code を tsumugi の中で動かすと、枠線が `- - - -` の破線になり、
消したはずのプロンプトが新しい描画の上に残っていた。

原因は East Asian **Ambiguous** 幅。`─` `│` `╭` `█` `●` `•` `·` `←` は
どれも Ambiguous で、`width_cjk()` は 2 を返す。tsumugi は桁の勘定を
`AmbiguousWidth::Wide` で固定していたので、TUI が 1 幅のつもりで書いた字を
2 桁で置いていた。**枠が飛び飛びになり、消去とカーソル移動の桁もずれる**ので、
古い文字が消えずに残る。かな・漢字は Wide クラスなので無関係。

`arch.md` §6.1 は最初から `ambiguous_width` を設計に入れていたが、
配線されていなかった（どこも `Wide` 決め打ち）。配線して**既定を 1 幅に変えた**。
設計時の既定（2・日本語端末の慣習）とは逆だが、TUI が崩れるほうが害が大きい。
2 幅が要るなら `[font] ambiguous_width = "wide"`。

プロセス全体で 1 つと決める（`tsg_term::set_ambiguous`）。ペインごとに違うと、
同じ文字列がペインをまたいだ瞬間に幅を変え、桁の勘定がどこかで必ず食い違う。

## 1. エージェントの状態

何本も走らせると、**どれが返事待ちかを目で探す時間**が仕事の大半になる。
それを消すのがこの節の全部。

**状態は推測しない。** 画面を読んで「いま返事待ちだろう」と当てにいく実装は、
相手が出力の形を変えた日に黙って壊れ、壊れたことにも気づけない。
名乗る口を開けて、エージェント自身のフックから呼ばせる。

```
tsg --install-agent-hooks          # Claude Code / Codex に配線する
tsg --agent-state blocked          # フックが呼ぶ 1 行
```

| フック | 意味する状態 |
|---|---|
| `SessionStart` | idle |
| `UserPromptSubmit` | working |
| `Notification`（許可待ち） | **blocked** |
| `Stop`（喋り終わった） | **done** |

状態はサーバが持つ。窓を閉じて開き直しても「どれが返事待ちか」が残る。
名乗らないペイン（ただのシェル）は、シェル統合が入っていれば
OSC 133 から「走っている」だけ分かる。それも無ければ印を出さない。

設定ファイルを直接触るので、既にある設定は消さない・2 回入れても増えない・
`--uninstall-agent-hooks` で足した分だけ消える。テストで押さえてある。

## 2. 見せ方

- タブに `●` 返事待ち / `✓` 終わった / `✕` 失敗 / `◍` 動いている。
  タブの印は**そのタブで一番強い状態**を出す。3 つ並んでいて 1 つが
  返事待ちなら、そのタブは返事待ちとして見えないと意味がない。
- ステータス行に `● 返事待ち N`。**押すとそこへ飛ぶ。**
  数を見せるだけでは、探すのは結局手作業になる。
- `Space a` でも飛ぶ。押すたびに順に回る（同じ 1 本へ戻らない）。
- 状態が**変わった瞬間**に、窓が裏に居るときだけタスクバーを光らせる。
  ずっと返事待ちのものを見るたびに光らせても、すぐ無視するようになる。

`⚑` は Consolas にも MS ゴシックにも無く、実機で空白になった。
記号だけに頼らず言葉を添える形（`● 返事待ち 1`）に変えた。

## 3. 外から回す

```
tsg --agents                              # session<TAB>pane<TAB>state
tsg --prompt "テストを直して" --wait        # 投げて、返事待ちになるまで待つ
tsg --wait --until done --timeout 600     # 終わるまで待つ（0 = なった / 2 = 時間切れ）
tsg --open README.md --render             # 走っている窓でファイルを開く
```

終了コードで答えるので `if tsg --wait --until blocked; then …` と書ける。

## 4. エージェントの出力を読む

- `[a` `]a` で発話単位に移動。行頭の印（`⏺` `●` `✻` …）を手がかりにする。
  **形が変わっても壊れず、動かなくなるだけ**。状態を当てにいくのとは違い、
  間違った答えを返す余地がない。
- `Space f` で画面に出てきたファイルの一覧。エージェントは触ったファイルを
  字で言うので、その字を集めれば足りる。`Read(...)` のような書式を
  覚え込ませると、その日のうちに古くなる。

## 5. Markdown を読む形にする

`Space m` か下の `◱ 読む形`、外からは `tsg --open x.md --render`。

**出力は ANSI 付きの文字列にして端末に食わせる。** 既に端末の解析器を
持っているので、色や太字を自前の構造で持ち回るより道が 1 本で済み、
描画・選択・コピー・Ctrl＋クリックがそのまま効く。専用の描画経路を増やさない。

- 読む形のあいだは編集できない。写しなので、直しても元のファイルに入らない。
  **入ったように見せない。**
- **コードブロックの中は一切解釈しない。** ここを解釈すると、
  マークダウンの説明を書いた文書が読めなくなる。
- リンクの URL は捨てず薄く残す（Ctrl＋クリックで開けるように）。
- 表は桁をそろえる。幅は 20 桁で下限を切る（狭すぎる紙面は読めない）。
- 読む形かどうかはサーバが持つ。開き直しても戻らない。

## 6. 端末の中から起動したらタブが増える

端末エミュレータを端末の中から起動するのは日常なので、そのたびに窓が
増えるのは邪魔でしかない。ペインに `TSUMUGI_SESSION` を渡して「中に居る」
ことを伝え、中から `tsg` と打たれたら**いまの窓のタブが増えて切り替わる**。
`-n` / `--new-window` で今までどおり窓が開く。繋がらなければ窓を開く
（開かないより、窓が開くほうがまし）。

## 実機で確かめたこと

- `claude` を中で動かす → 枠線が実線に戻り、消えずに残っていた
  前のプロンプトも消えた（信頼確認の画面と本画面の両方）
- `tsg --agent-state blocked` → `tsg --agents` が `default 1 blocked` を返す
- タブに `●`、ステータスに `● 返事待ち 1` が出る
- `tsg --wait --until blocked` が 0、`--until failed --timeout 3` が 2
- `TSUMUGI_SESSION=default tsg` → 窓が増えずにタブ 2 が開いて切り替わった

## まだ実機で見ていないもの

  選ぶところ（`next_waiting`）は単体テストで押さえたが、画面での確認は
  取れていない。**このPCの Smart App Control が、ビルドし直すたびに
  新しい exe を数分ブロックする**ため、実機確認の口が細い。
- Markdown の読む形の見た目。組み立ては単体テストで押さえてある
  （見出し・記法が消えること・リンクの URL が残ること・コードブロックを
  解釈しないこと・表の桁・折り返し）。

## このPCの環境

`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState`
が 1（Smart App Control が有効）。署名の無い実行ファイルは、**ビルドし直して
ハッシュが変わるたびに数分〜十数分ブロックされる**（`os error 4551` /
`Permission denied`）。ビルドは成功して起動だけ落ちるので、コードを疑う前に
ここを思い出す。tsumugi 自身も、入れ直した直後は同じ理由で起動しないことがある。
