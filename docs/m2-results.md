# M2 実測結果 — mux の分離

`arch.md` §9 の M2 と、§4 の不変条件 4「mux は常に別プロセス」の判定。

実測日: 2026-08-23 / Windows 11 Pro 26200 / x86_64 / debug ビルド

---

## 結論 — 🟢 通過。**共有メモリの高速経路は不要**

不変条件 4 は「レイテンシと引き換え」であり、`arch.md` §4 は
**入力 → 画面反映が 8ms を超えるならグリッド転送に共有メモリ経路を足す**と決めていた。

実測の結果、その退避策は要らない。

| 指標 | 実測 | 予算 |
|---|---:|---:|
| IPC 往復 中央値 | **0.055 ms** | 4 ms |
| IPC 往復 p95 | 0.073 ms | — |
| IPC 往復 最悪 | 1.854 ms | 8 ms |

200 回計測（`cargo test -p tsg-mux --test latency -- --nocapture`）。
Windows の名前付きパイプ + JSON Lines、debug ビルドでこの値。
8ms の予算に対して**中央値で 70 倍以上の余裕**がある。

→ `arch.md` §11 の未決事項 1「JSON Lines のまま出荷するか msgpack へ移すか」は
**JSON Lines のままで確定**。デバッグ可能・外部からスクリプト可能という利点を、
性能のために手放す理由がない。

回帰テスト `ipc_round_trip_stays_within_the_latency_budget` で 4ms を上限に固定した。

## 出口条件 — ウィンドウを閉じてもプロセスが生き、再アタッチできる

**ヘッドレス**（`cargo test -p tsg-mux`、4 件）

| テスト | 内容 |
|---|---|
| `panes_survive_a_disconnected_client` | コマンドを実行 → クライアントを落とす → 再接続 → **スナップショットに実行結果が残っている** |
| `explicit_detach_keeps_the_session_alive` | `Detach` 後に入り直すと同じペイン ID が居る |
| `splitting_creates_a_second_pane_in_the_layout` | 分割がレイアウト木に反映される |
| `protocol_version_mismatch_is_reported` | 版違いを握り潰さない |

**実プロセス**

```
1回目: mux セッション 'pc2' を新しく起こします / mux サーバを起動しました
       → GUI を強制終了 → tsg.exe が 1 個残る（＝サーバ）
2回目: 既存の mux セッション 'pc2' に再接続しました
       → GUI 終了後も 1 個のまま
```

## 潰した不整合

### 1. listener のバインドが非同期で、接続が競合する

`spawn()` がソケットを開き終える前に返っていたため、直後に繋いだクライアントが
全部「接続できない」で落ちた（統合テスト 4 件が同時に失敗）。
**バインドは同期処理にし、accept ループだけをスレッドへ渡す**よう直した。

### 2. サーバ子プロセスが GUI と道連れになる

`Command::spawn` の既定では子が親のプロセスグループに属するため、GUI を強制終了すると
**サーバも一緒に死に、「ウィンドウを閉じてもシェルは死なない」という約束が破れていた。**
Windows は `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`、Unix は `process_group(0)` で
明示的に切り離した。実プロセスで確認済み（上記）。

### 3. セッションを終わらせる手段が無い

デタッチしかないとサーバが溜まり続ける。配置モードに `Q`（セッションごと終了）を追加した。

## 設計上の判断: グリッド差分ではなく PTY の生バイトを送る

サーバ → クライアントは **PTY の生バイト（base64）** を流し、クライアントは自前の
`tsg-term` で解析して自分のグリッドを作る。差分の直列化を実装しなくて済み、
プロトコルが端末仕様に引きずられない。

再アタッチのときだけ、サーバが持つグリッドを**確定した行の列**として送る。

⚠️ 現状のスナップショットは平文なので、SGR（色・属性）を実装したら
そこも運べる形に変える必要がある。M3 で SGR を入れるときの宿題。
