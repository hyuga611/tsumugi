# M4 結果 — 内蔵エディタとオペレータ

`arch.md` §9 の M4。出口条件は「nvim を入れずにファイル編集が完結する」。

実施日: 2026-08-24 / Windows 11 Pro 26200 / x86_64

---

## 1. 出口条件 — 🟢 通過

実機での往復:

```
:e edit-demo.txt   → ファイルがペインに開く（ステータスに名前と未保存の *）
6j dd              → 行が消える
gg 2j ==           → JSON が字下げされる
:w                 → ディスクに書かれる（実ファイルで確認）
:q                 → 端末に戻る。シェルは走ったままなのですぐ続けられる
```

保存後のファイルを実際に読んで、削除・整形・日本語・改行コードのすべてが
意図どおりであることを確かめた。

## 2. 「エディタ内蔵が実質タダ」の中身

`FileBuffer` は `Buffer` トレイトを実装しているだけで、**モーションもテキスト
オブジェクトもオペレータも 1 行も書いていない**。`hjkl` `w` `b` `gg` `G` `%`
`iw` `i(` `if` … が最初から効く。`concept.md` が「タダになる」と書いたのは
この意味で、実際に追加したのはバッファの読み書きだけだった。

ペインは端末とファイルのどちらかを見せる（`PaneBuffer`）。**ファイルを開いても
下のシェルは走ったまま**で、`:q` で戻る。ペイン ID とレイアウトはサーバのものを
使い続けるので、分割も配置モードもタブもそのまま効く。

### 中身はサーバが預かる（プロトコル版 4）

編集そのものはクライアント（モーダルエンジンを持つ側）が行い、**結果をサーバへ渡す**。
保存もサーバが書く。これで「シェルは残るのにファイルは残らない」という非対称が消えた。

```
ClientMsg::OpenFile / SetFile / SaveFile / CloseFile
ServerMsg::FileState / FileSaved / FileClosed
```

実機での確認: ファイルを開いて `dd` → **保存せずに GUI を強制終了** → 起動し直すと
編集後の内容がそのまま戻り、ステータスに未保存の `*` も付いている。
ディスクは元のまま（保存していないので当然）。

⚠️ `SetFile` は差分ではなく**毎回全文**を送る。打鍵ごとにファイル長ぶんを送るので、
大きなファイルを扱う段で差分へ替える。取り消しの全文スナップショットと同じ判断で、
今は正しさと単純さを取っている。

## 3. オペレータ

| キー | 実装 | 備考 |
|---|---|---|
| `y` | 済 | M1 から |
| `!` | 済 | M3。範囲をプロンプトへ送る |
| `d` | 済 | 端末では**表示から消すだけ**。プロセスには何もしない |
| `c` | 済 | `modal-spec.md` §7 の可否表どおり File のみ |
| `=` | 済 | JSON の字下げと表の桁揃え。外部コマンドを呼ばない |
| `>` | 済 | 範囲を外部コマンドへ通し、結果を新しいペインで開く |
| `u` / `C-r` | 済 | 取り消し / やり直し。**1 操作 = 1 段** |

エンジンは `Effect::Edit { range, text }` を出すだけで、バッファを書き換えない
（`&dyn Buffer` しか持たない）。相手が端末のグリッドかファイルかを知っているのは
ホストだけ。`arch.md` の不変条件 2「`tsg-modal` は純粋」をここでも保った。

`=` を外部コマンドに投げないのは、**`jq` が入っているかどうかで挙動が変わる**のを
避けるため。判定できなかったものはそのまま返すので、散文を壊さない。

## 3.5 取り消し（undo）

差分ではなく**全文のスナップショット**を積む。差分を持つと、行単位と文字単位で
逆操作の形が変わり、境界を間違えたときに「取り消したら壊れた」が起きる。
取り消しは壊れないことが最優先なので、まず正しさを取った。
総量 4MB / 500 段で頭打ちにしてある（大きなファイルを扱う段で差分へ替える）。

**単位の切り方が肝。** 1 打鍵ずつ戻ると使い物にならないので、
`begin_group` をホストが呼ぶ位置で決めている:

- 入力モードに入るとき 1 回 → 打った分がまとめて 1 段
- オペレータの適用ごとに 1 回 → `dd` や `==` が 1 段
- `replace` は中で delete と insert を両方やるが、単位はその手前で閉じる（2 段にしない）

取り消すと `dirty` も一緒に戻る。戻したのに「未保存」の印が残ると嘘になるため。

端末の表示は履歴を持たない。`d` で消したものはサーバ側の控えに残っているので、
取り消しではなく**セッションに入り直せば戻る**。そう案内する。

## 3.6 `>`（外部コマンドへパイプ）

`>ap sort`、`>io jq .` のように使う。範囲が決まった時点でコマンドパレットが
`> ` を入れた状態で開き、通す相手を訊く。入り口を 2 つ作らずに済む。

- **シェル経由で走らせる。** ユーザーが書くのは `jq .` のようなシェルの文法で
  argv ではないため、自前で分解しない。
- **失敗しても標準エラーを見せる。** 黙って空を返すと何が起きたか分からない。
- プロセスを起こすのはクライアント側。PTY と違って一度きりの実行なので、
  サーバへ持たせず**結果だけ**セッションへ預ける（`PipeResult` 1 通で分割と生成をやる。
  2 通に分けると「今できたペインの ID」を追う必要が出て、取りこぼす余地ができる）。
- 結果のペインは保存先が無いファイルバッファ。`:w <パス>` で決めれば残せる。

## 4. 実機で見つけたもの

### 1. 日本語が重なって潰れた

`FileBuffer` が全角文字の「右半分」のスペーサセルを置いていなかった。
グリッドは置くので、**セルの添字と列が全角 1 文字につき 1 ずつずれ**、
文字が重なって描かれた。ASCII だけなら正常に見えるので、
日本語を入れて画面を見るまで分からなかった。

### 2. 整形結果の最後の行が次の行にくっついた

`=` で JSON を整形したら、閉じ括弧が次の行の頭に刺さった。
「消してから同じ位置へ差し込む」を行単位の範囲にそのまま使ったのが原因で、
行単位は**行ごと入れ替える**必要がある。`FileBuffer::replace` に分離して直した。

### 3. 使い方を出している間、クリックが下の本文に抜けた

キーは「どれか押すと閉じる」で捕まえていたのに、**マウスは素通りしていた**。
見えていない端末に文字が入り、`:e ...` がそのままシェルへ流れた。
クリックでも閉じるだけにした。一覧（メニュー・パレット）は最初から
最優先で捕まえていたのに、使い方だけ抜けていた。

### 4. ファイルの上でクリックすると入力モードに入った

クリック時のモード判定が「端末の生きた末尾より下か」だけを見ていて、
**ファイルを開いていても端末のカーソル位置で判断していた**。
エディタで文字を置きに行っただけで入力に入るのは事故なので、
ファイルではクリックはカーソル移動だけにした。

どれも回帰テスト付き。どれも画面を見なければ気づけなかった。
