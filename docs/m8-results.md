# m8-results — 仕上げ。リガチャ・テーマ・設定の読み直し・RPC の口、と安全側の作り直し

M8 は「毎日これだけで回せるか」を出口条件にした回。足りなかったのは
**見た目を自分に合わせる手段**と、**外から動かす口**、そして
**同じマシンの他人から守られていること**だった。

---

## 0. 先に、直した穴

機能を並べる前にこれを書く。M7 まで、**mux ソケットが同じマシンの他ユーザから
到達できた**。

- **Linux**: 抽象名前空間（`@name`）はパーミッションを一切持たない。誰でも繋いで
  読み書きできる。書ければシェルへ任意のキーを送れる＝そのユーザとして任意コード実行。
- **Windows**: 名前付きパイプの既定のセキュリティ記述子は Everyone に読みを与える。
  画面の内容（鍵・パスワード・トークン）が他のユーザから読める。
- 名前にユーザの区別が無く、多人数のマシンでは**先に起動した人のセッションへ
  繋がる**。衝突がそのまま事故になる。

直した形:

| | 置き場所 | 誰が触れるか |
|---|---|---|
| Unix | `$XDG_RUNTIME_DIR/tsumugi/`（無ければ `/tmp/tsumugi-<uid>/`） | 0700 のディレクトリ、ソケットは mode 0600 |
| Windows | `\\.\pipe\tsumugi-<印>-<名前>.sock` | 現在のユーザ SID だけを許す DACL |

**閉じられなければ開かない。** 自分だけに閉じたソケットを用意できない環境では、
サーバは起動に失敗する。開いた口を黙って使わせるより、起動しないほうがいい。

Windows は DACL だけでは足りない。`\\.\pipe\` は誰でも名前を作れる名前空間なので、
先回りして同じ名前のパイプを立てておく手（squatting）が残る。DACL は「自分の口を
他人に読ませない」ためのもので、「他人の口へ自分が繋いでしまう」のは防げない。
そこで**クライアント側でも繋いだ先のプロセスの所有者を確かめる**。開けなければ
「自分のものではない」と答える（迷ったら繋がない側へ倒す）。

同じ回に見つけて直したもの:

- `sessions` の控えを `/tmp` 直下に置いていた。ここに書ける他人が居ると、
  一覧に偽のセッション名を並べられる（選ぶとその名前でサーバが起きる）。
- **OSC 0/2（タイトル）と OSC 7（cwd）を素通ししていた。** 中身は子プロセスが
  自由に決められる。制御文字が混ざればステータス行の見た目が壊れ、長さに上限が
  無ければメモリがそのぶん伸びる。制御文字を落として長さを切った。
- **スクロールバックに上限が無かった。** 出しっぱなしのプロセス 1 つ（`yes`、
  巨大なログの `cat`）でメモリが尽きる。既定 1 万行にして、あふれた分は先頭から捨てる。
- 捨てた行数だけ**セマンティックマークを寄せる**。寄せないと、ガターの印と
  `[[` `]]` が無関係な行を指す。同じ理由で、`d` による行削除でも印が置き去りに
  なっていた（こちらは M3 からの潜在バグ）。`TermState` 経由に一本化した。
- `:w` が `fs::write`、つまり**先に切り詰めてから書いていた**。途中で落ちると
  元の中身も新しい中身も無い空のファイルが残る。エディタとして起こしてはいけない
  事故なので、同じディレクトリへ書いて `fsync` してから `rename` する形にした。

**良かったところも書いておく。** OSC 52（クリップボード）を実装していなかったのは
正解だった。あれば `cat` した 1 行でクリップボードを読み書きされる。
PowerShell へ流す文字列の引用も正しく、`unsafe` は 3 か所だけで、いずれも
`windows-sys` の呼び出しに閉じていた。

方針は `SECURITY.md` にまとめた。**信頼境界は mux ソケット 1 本**で、
そこに繋げる者はそのユーザとして何でもできる。だから錠はそこだけに集める。

## 1. リガチャ

端末は格子なので、シェーピングの送り幅をそのまま使ってはいけない。
合字の字形は入力の何文字ぶんかを 1 つの**クラスタ**として返すので、
**クラスタの先頭が何セル目か**を見て置く。等幅フォントの合字はその字数ぶんの
幅に設計されているので、これで格子と合う。

組むのは `FontStack::shape_cells`（`(グリフ, 何セル目)` を返す）。
レンダラから切り離してあるので、**GPU 無しで試験できる**。

run を切るところ:

- **色が変わるところ。** 合字は 1 つの字形なので、途中で色を変えられない。
- **カーソルの居るところ。** 下の字が何だったか見えないと直せない。

`->` を含まない行のほうが圧倒的に多い（日本語の文章にも `ls` の出力にも合字は
出ない）ので、合字になり得る字を含まない run はシェーパへ渡さない。
組んだ結果は行単位で控える（上限つき）。

## 2. テーマ

**書くのは「素」の色だけ。** 背景・前景・カーソル・選択と、端末の 16 色。
これは世の中のテーマが既に持っている形なので、手持ちの配色をそのまま移せる。
ステータス行・パネル・区切り・モード帯といった飾りは、そこから決まった規則で
**導く**。40 個の色を手で揃えさせない。

導いた値は個別に上書きできる。規則は大体うまくいくが、どうしても合わない
1 個が必ず出る。そこで設計が詰むのを避ける。

組み込みは 3 つ。**夜霧**（暗い / 既定）・**墨**（暗い・高コントラスト）・
**白磁**（明るい）。暗いテーマだけを配るのは「昼に使えない」と同じで、
明るいところでは白地でないと読めない。

```toml
[theme]
name = "白磁"

[theme.colors]
background = "#faf9f6"
ansi1      = "#c0393f"
```

綴りを間違えた名前と読めない色は**黙って捨てず警告に出す**。
「書いたのに効かない」で終わらせない。

**16 以降のインデックス色はテーマで動かさない。** アプリが `\x1b[38;5;208m` と
書くとき期待しているのは決まった橙で、そこを振り替えると出力が嘘になる。

コントラストはテストで固定した。前景と背景、ステータス行、そして**モードの帯**
（塗りつぶしの上に字が載る）。実際にこれが白磁で落ちて、帯の作り方が間違って
いると分かった。背景へ寄せる規則を明るいテーマにそのまま当てると、帯まで
明るくなって字が消える。帯だけは常に「濃くする」向きへ動かす。

## 3. 設定のホットリロード

**設定を直すために端末を閉じさせない。** 色や文字の大きさは「試して直す」もの
なので、1 回ごとに開き直させると誰も詰めない。

監視ライブラリは入れなかった。見たいのはファイル 1 つで、間隔も 1 秒でよく、
そのためにプラットフォーム別のイベント機構を抱えるのは釣り合わない。
すでに回っている 8ms のティックの上で、700ms ごとに更新時刻を見るだけにした。

- 反映するもの: テーマ / 不透明度 / ぼかし / 文字の大きさ / 合字 / スクロールバック
- **言語だけは変えない。** `t!` は起動時に決めた値を見るので、途中で変えると
  画面の一部だけ古い言語のまま残る。変えたことは伝えて、次に開いたときからと言う。
- **コマンドラインの指定は読み直しても勝つ。** 設定ファイルに引きずられて
  `--opacity 1.0` で開いた窓が勝手に透け始める、を起こさない。
- 壊れた設定は当てずに、何が悪いかだけ出す。起動時は既定へ倒すが、動いている
  途中で既定へ戻すと、それまでの見た目まで巻き戻って驚かせる。

コマンドパレットに「設定ファイルを開く」を足した。開いて `:w` すればその場で
効くので、**設定を詰める道がこれ 1 本でつながる**。

## 4. RPC の口

mux は最初から別プロセスの JSON Lines で話しているので、外から叩ける口は
もともと在った。ここでやったのは、それを**人と台本が使える形にして、
約束として公開する**こと。形は `docs/rpc.md`。

```sh
tsg --list                      # 走っているセッション（繋がるものだけ）
tsg -s work --send 'ls -la\n'   # いまのペインへ入力を流す
tsg -s work --capture           # 見えているものをテキストで
tsg -s work --tap               # 生バイトを覗く
tsg -s work --rpc               # 生のプロトコルを標準入出力で話す
```

`--capture` が返すのは、サーバが再アタッチ用に持っている画面そのもの。
取り出し専用の別経路を作っていないので、**窓に見えているものと食い違わない**。

`--rpc` は逃げ道として最初から開けた。便利な口をいくつ足しても
「それでは足りない」は必ず来る。そのときにこちらの実装を待たせない。

### 版 8

`attach` の `cols` / `rows` に **0（＝大きさを持ち込まない）** を足した。
窓を持たない台本が適当な 80x24 を名乗ると、その後に開くペインまでその大きさに
なっていた。`--send` を 1 回叩いただけで次のペインが縮む、という筋。

## 5. アイコン

平らな山形をやめ、**1 本の平たい紐を折り返した形**として描き直した。
名前が紡ぐことなら印もそう在るべきで、ただの折れ線にはしない。

板に斜めの織り目と上端の光。紐は斜めのグラデーションに縁の光と陰、
折り返しの陰、板へ落ちる影。カーソルには淡い光。

**輪郭は触らない。** 立体に見せる細工は全部シルエットの内側に入れてある。

外形をいじる案は実際に試して捨てた。2 本の紐を交差させ、頂点から先を
行き過ぎさせて組んで見せる案で、大きく出すと悪くないが、**32px で
「組んだ紐」ではなく「折れた棒」に見える**。凝りたい欲を「まず `>` に
読めること」より先に出さない、と決めて捨てた。

## 7. ここで踏んだ罠

**アイコンの織り目が板を真っ白に塗り潰した。**

`Image.paste(layer, mask)` は**マスクだけを不透明度に使い、色側のアルファを
見ない**。`(255, 255, 255, 10)` で薄く敷いたつもりの織り目が、マスクの形どおり
不透明に乗っていた。色のアルファをマスクへ掛ける形に直した。

同じ回に、`.rs` と `.md` の CRLF を一括で LF へ直そうとして、**PNG と ICO を
壊した**。「CR を含むファイル」を対象にしたので、バイナリが引っかかった。
git から戻して事なきを得たが、baseline を先にコミットしていなければ
再生成できないものが消えていた。

**ステータス行が消えたと誤診した。** 実機の画面を撮ると、下端に何も無い。
`draw_status` を疑い、`self.rows` を印字するところまでやって、原因は
**撮り方**だった。このマシンは 125% 表示で、撮影に使った PowerShell が
DPI 非対応だったため、Windows が数字ごと縮めて渡していた
（アプリから見て 1375x875 の面が 1100x700 として見える）。撮った絵は
縮小版で、いちばん下の行が潰れていた。

直したのは 2 か所。**どんな窓の寸法を聞く前に**
`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` を呼ぶこと。そして
`PrintWindow` は**窓ぜんぶ**（タイトルバーを含む）を描くので、
`GetClientRect` の大きさで受けると下からその高さぶんが切れること。
どちらも「アプリが壊れている」ように見える切れ方をする。

ついでに分かったこと: **使い方の面（F1）を出している間はステータス行を描かない。**
仕様どおりだが、撮った絵だけを見ていると区別が付かない。

## 8. 実機で確かめたこと

`--release` を建てて、実際に開いて確かめた。

- **設定の読み直し**: 窓を開いたまま `config.toml` を書き換え、夜霧 ⇄ 白磁が
  その場で入れ替わることを撮って確認した。不透明度とぼかしも一緒に効く
- **明るいテーマ**: ステータス行のモード帯（青地に白）が白磁でも読めること。
  コントラストの試験が守っている条件を、実物でも見た
- **RPC**: `--list` / `--send` / `--capture` / `--rpc`（双方向・壊れた行の扱い・
  `shutdown` まで）を走らせた
- **アイコン**: 16 / 20 / 24 / 32 / 48px を並べて実物で見た
- **合字**: このマシンには合字を持つ字体が 1 つも入っていない（Consolas だけ）。
  **なので実物では確かめられていない。** 代わりに `--diagnose` が
  「Consolas は合字を持っていません（設定を on にしても出ません）」と言うようにし、
  組む側は「どのグリフも実在するセルに左から順に置かれる」を試験で固定した。
  Windows の候補に **Cascadia Code** を Mono より先に足したので、入っている
  マシンでは既定で効く
