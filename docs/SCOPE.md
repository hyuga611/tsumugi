# SCOPE — やること・やらないこと

> 次に何を足すか決める前に読む。**足す理由を中心命題から導けない機能は、足さない。**

## なぜこのファイルがあるか

tsumugi の前身 rindo は、機能と性能の検討がまとまらないまま増え続け、2026-09-02 に削除した。
tsumugi は公開から 9 日で 4 万行を超えている。同じ軌道に乗らないために、境界を紙に固定する。

設計判断の正本は `concept.md`（何を捨て何を取るか）と `arch.md`（構成とマイルストーン）。
このファイルはそれらを書き換えない。**入口の門だけを担う。**

## ものさし

> グリッドはドキュメントである。プロセスはその末尾に追記しているだけの存在にすぎない。

新しい機能は、この一文か、`concept.md` の「これさえあれば」の 5 条件のどれかから導けること。
導けなければ入れない。

1. nvim を別に入れる理由が無い
2. tmux を起動する理由が無い
3. スクロールバックのコピペで道具を持ち替えない
4. 日本語入力・CJK 幅・IME が壊れない
5. ログの中のパス・URL・エラー行が「掴んで次に渡せる」ものとして振る舞う

## やること（v1 の範囲）

- 上の 5 条件を満たすこと。M0〜M12 で実装済み。
- 実機で踏んだ「入れたのに動かない」「行き止まり」の修正。0.3.x はすべてこれ。
- 3 OS で同じに動くこと。macOS / Linux は未検証で、検証は範囲内、新機能ではない。
- 外から駆動する口（`rpc.md`）の互換維持。語彙を足すのは可、既存を壊すのは不可。

## やらないこと

`concept.md` の「捨てるもの」6 項と「非目標」はそのまま生きている。
加えて、公開後に境界が曖昧になったものを明示する。

| やらない | 代わりに |
|---|---|
| AI エージェントを**動かす**（起動・並列制御・課金・プロンプト管理） | 状態を**名乗らせて表示する**まで（M10）。動かすのは hooks と外部ツールの仕事 |
| Markdown / 差分 / 画像の専用ビューア | 端末に食わせて描く（ANSI 化・Kitty graphics）。描画経路を増やさない |
| 内蔵エディタの IDE 化（LSP・補完・デバッガ） | `Buffer` として編集できる範囲まで。LSP は v1 の範囲外（`arch.md` §11） |
| 設定のためのプラグイン機構 | RPC の口に載せる（`register_command`）。`config.lua` は設定の計算だけ |
| 既存ターミナル・tmux・vim からの設定移行 | 書かない |
| SSH / Web ターミナル / リモート GUI | ssh は子プロセス。mux は同じマシンの自分だけ（`SECURITY.md`） |
| 通知・チャット・タスク管理など、ターミナルの外の機能 | 書かない |

## 新機能の入れ方

1. ものさし 1〜5 のどれから導けるかを 1 行で書く。書けなければ
   `airframe discard "<件名>" "<理由>"` で台帳に落として終わる。
2. `mouse-parity.md` に行を足す。マウス等価が無い機能は入れない。
3. 実機で使って結果を `docs/m*-results.md` に書く。テストが通っただけでは実装済みと呼ばない。

## v1 の終わり

上の 5 条件を、Windows / macOS / Linux の実機で本人が毎日使って満たしたとき。
そこから先は「直す」だけで「足す」は原則しない。足したくなったら、このファイルを先に書き換える。
