## 1. 起動が 1 コマンドになった

それまでは、ビルドした exe の場所を覚えて叩くしかなかった。
他のターミナルがインストーラで済ませていることを、1 コマンドにまとめた。

```
tsg --install
```

- スタートメニューとデスクトップにショートカット（アイコン付き）
- ユーザーの PATH に登録（新しいシェルから `tsg`）
- フォルダの右クリックに「tsumugi でここを開く」（`--cwd "%V"` を渡す）
- `tsg --uninstall` で全部戻る

**exe はコピーしない。** 今ある場所を指すだけにした。コピーする形にすると、
置き場所によっては実行が止められる環境があり（このPCがそう）、
「入れたのに起動しない」という一番たちの悪い失敗になる。

ショートカットとレジストリは PowerShell 経由で触る。`.lnk` を自前で書くより、
OS の口（WScript.Shell）を叩くほうが壊れない。触るのは HKCU だけで、管理者権限は要らない。
**何を変えたかは必ず画面に出す。** 黙って環境を書き換えない。

## 2. アイコン

`assets/icon.py` が作り方を持つ（絵をバイナリで抱えない）。
暗い角丸の板に、琥珀のシェブロンと青いカーソル。**16px で崩れないこと**を最優先にして、
線を太く・要素を 2 つだけにした。

- `icon.rgba` — 256×256 の生 RGBA。ウィンドウとタスクバー用。
  実行時に画像デコーダを持ち込まないために、デコード済みで埋め込む。
- `tsumugi.ico` — ショートカットと Explorer 用（16〜256 の多重解像度）。
  これもバイナリに埋め込み、`--install` のときに書き出す。

## 3. UI の作り直し

**キーバインドを覚えていない人が読む場所**として作り直した。

### ステータス行

前: `≡ ? 録  -- 通常 --  IME:切 ⌨自🖱自`
後: `≡ メニュー  ? 使い方  ● 記録  [通常]  読むモード クリックで選ぶ / …`

- 押せるものは**言葉入りのボタン**にした。記号だけだと押せると気づかれない。
- モードは**色帯**にした。字を読まなくても、今どちらかが分かる
  （入力＝青 / 読む＝緑 / 選択＝橙 / 配置＝紫）。**押すと入力 ⇄ 読むが切り替わる。**
  キーを知らない人がモードを行き来する唯一の手段になる。
- 右の `IME:切 ⌨自🖱自` は消した。IME はモードから分かるし、所有権は
  **子プロセスが持っているときだけ**出せばいい。普段は静かにしておく。
- 残りの幅に、今できることを**言葉で**書く。キー名の羅列ではなく「何が起きるか」。

### 使い方（F1）

キー一覧の羅列をやめ、**「マウスだけで使えます」から書く**。
次に「2 つのモードがあります」、最後に「キーで速くしたくなったら」。
全部の一覧はコマンドパレットが持っているので、ここでは代表だけ出す。

### 右クリックメニュー

20 項目を平らに並べていたのを、**編集 / ファイル / 画面 / セッション**の見出しでまとめた。
見出しはキーでも飛ばす（押しても何も起きない行で止まらない）。

### コマンドパレット

下に 1 行足した: 「↑↓ で選ぶ · Enter で実行 · Esc で閉じる · そのまま打つと絞り込み」。
**一覧を出したのに動かし方が分からない**、を作らない。

## 4. 日本語と英語

`[ui] lang = "auto" | "ja" | "en"`（`tsg --lang en` でも切り替わる）。
書かなければ OS の表示言語を見る。

訳は `t!(日本語, English)` で**同じ行に並べて**書く。別ファイルの表に逃がすと、
片方だけ直してもう片方が古いまま、が必ず起きる。
言語はプロセス全体で 1 つ（起動時に決まって変わらない）。見るのは**表示用の文字列だけ**で、
モード機械の判断は言語に依存しない（`arch.md` の不変条件 2 は保たれる）。

コマンドの題名は `CommandSpec` が両方を持ち、**片方が空だとテストが落ちる**。

## 5. 既定で透けてぼける

`opacity` の既定を 1.0 → 0.90 にした。不透明が既定だと「透過は設定でできる」で終わり、
初めて開いた人がこの端末の見た目を知らないまま使うことになる。
不透明にしたいときだけ `opacity = 1.0`。

## 6. ここで踏んだ罠

**画面を撮ったら真っ白で、描画が壊れたと誤診した。**

`Graphics.CopyFromScreen`（GDI）は、DirectComposition で出しているウィンドウを
真っ白で返すことがある。透過を既定にした直後だったので、透過の実装を疑って
しばらく探した。実際にはアプリは正しく描けていて、**撮り方が悪かった**。

検証ドライバを `PrintWindow(PW_RENDERFULLCONTENT)` に替えた。窓そのものに描かせるので、
合成のされ方に左右されない。ついでに窓だけが撮れるので、画面の他のものが写り込まない。

（同じ回に、検証ドライバへ日本語コメントを足して PowerShell 5.1 のパースを壊した。
BOM 無し UTF-8 を ANSI として読む例の罠で、ドライバは ASCII に保つのが早い。）
