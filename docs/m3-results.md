| セッション一覧 UI | **未着手** |

### SGR

16 色 / 256 色 / 24bit RGB、太字・淡色・斜体・下線・点滅・反転・非表示・取り消し線。
`38;5;n` と `38:5:n`（コロン形）の両方を受ける。現実に両方飛んでくる。

**消去は背景色で行う**（xterm 以来の挙動）。これが無いと色付きの `clear` が抜けて見える。
全角文字の右半分（スペーサセル）も同じ属性を持たせる。持たせないと背景の帯が縞になる。

`Color::Default` の実 RGB は描画側の 1 箇所（`cell_colors`）でしか解決しない。
テーマを差し替えるときに触る場所を増やさないため。

背景は**同色の連なりを 1 枚の矩形にまとめて**塗る。セルごとに出すと 80×24 で
2000 枚近くになり、色の無い画面でもその代金を払うことになる。

### スナップショットが色を運ぶ（プロトコル版 2）

サーバは再アタッチ時に**行を SGR 付きの ANSI として**送り、クライアントは
同じ `tsg-term` で解析する。復元専用の描画コードを持たずに済む。

行末は落とすが、**既定でない背景色を持つセルは落とさない**。
プロンプトの色帯が行末まで伸びている表示（パワーライン系）が切れるため。

### 分割比

`Layout::Split` に `weights` を足した。**サーバのレイアウト木が持つ**ので、
再アタッチしても分割比が戻らず、複数クライアントでも食い違わない。
`#[serde(default)]` にしてあり、重みが壊れていれば均等に読み替える。

## 2. テキストオブジェクト（`modal-spec.md` §6）

汎用（`iw` `aw` `iW` `aW` / 引用符 / 括弧 / `ip` `ap` / `is` `as`）と、
ターミナル固有（`ic` `ac` `io` `ao` `if` `af` `iu` `au` `ih` `in` `an` `ie` `ae`）。

要点は**セル列と文字列の写像**。全角は 2 列 1 文字、結合文字は 1 列 n 文字なので、
`chars` の添字と列番号は一致しない。両方を持って解いている（`Scan`）。

判定で気をつけたところ:

- `if` は `:` を境界にする。しないと `src/main.rs:42` の `42` まで飲む。
  一方 `C:\Users\...` の `:` はパスの一部なので、ドライブレターだけ後から取り込む。
- `foo` を勝手にパス扱いしない。区切りを含むか、拡張子らしき尻尾を持つことを要求する。
- URL の `(` `)` は URL 文字でもある。`(https://example.com)` を掴んだとき
  頭の非英数を落としてから判定し、`au` で改めて括弧を含める。
- `ih` は 7 桁以上の16進で**数字と英字が両方ある**ものだけ。`deadbeef` は拾わない。

### ダブルクリックが同じ関数を通る

`at_pointer` は狭いものから順に当てて最初に成立したものを返す（URL → パス → ハッシュ →
数値 → 単語）。**キーボードの `vif` とマウスのダブルクリックが同じ `textobj` を通る**ので、
片方だけ賢くなって食い違う、が起きない。

`src/main.rs:42` の上でのダブルクリックは `src` ではなく `src/main.rs` を取る。
ここが既存のターミナルとの分かれ目。

## 3. マウス操作層（`mouse-parity.md`）

`Command::Select { range }` を足した。`Apply` が「範囲＋動詞」の合流点なのに対し、
こちらは「範囲だけ」の合流点。ドラッグもダブルクリックもガターも、
テキストオブジェクトも、全部ここへ落ちてから同じディスパッチャを通る。

### alt-screen 委譲（§5）

所有権が子にあるときは SGR 1006 / urxvt 1015 / utf8 1005 / レガシーの各形式で送る。
トラッキング段階も尊重する（1000 で移動を送らない、X10 で解放を送らない）。
**alt だがマウスレポートを要求していない**（`less` 等）ときは、慣例通り
ホイールを矢印キーへ変換する。

ステータス行のマウスバッジをクリックすると所有権を tsumugi に固定する（`C-\` と等価）。

### 左ガター

OSC 133 のブロックをそのまま印にする。**出力を正規表現で当てにいかない**ので、
嘘の印が出ない。色と太さの両方で区別する（成功=細い緑 / 実行中=中くらいの橙 / 失敗=太い赤）。
記号ではなく矩形なのは §5-2 の理由。

1 クリックでコマンドブロック全体（`ac`）、2 クリックで出力だけ（`io`）を選択する。
キーボードの `vac` / `vio` と同じ関数を通る。

⚠️ ガターは**本文の桁数を 2 減らす**。PTY へ伝える桁数もそれに合わせている。
ここがずれるとシェルの折り返しと画面の折り返しが食い違って行がにじむ。

## 4. メニューとパレット、そして残り

### 項目はレジストリから生成する

右クリックメニューもコマンドパレットも、項目を手で並べていない。
`REGISTRY` を走査して、`MousePath::Menu(_)` のものをメニューに、
`in_palette` のものをパレットに出す。**手で並べたメニューは必ず腐る**
（機能を足した人が更新を忘れる）ので、そこを構造で潰した。

選ばれた項目は `Engine::invoke(id)` を通り、キーボードと同じ `Command` に落ちる。
メニュー専用の副作用がゼロなので「キーでは効くのにメニューからは効かない」が起きない。

メニューの最後には必ず**コマンドパレット…**を置いた。これで、メニューに出ていない
コマンドでも **メニュー → パレット → 選択** の 2 アクションで届く（§1.1 の約束）。

新しく足したテスト `every_palette_reachable_command_can_actually_be_invoked` が、
**宣言だけして実行できない項目**を落とす。実際にこれが `register.select` を捕まえた
（`"` は続きの 1 文字が要る）。キーで打ったのと同じ待ち状態に入れて解決した。

## 4.5 起動と見た目（他のターミナルと並べて使えるか）

「ターミナルから起動できるか」「透過やぼかしができるか」は見た目の問題ではなく、
**常用できるかどうか**の問題なので、ここで片付けた。

| | 前 | 今 |
|---|---|---|
| Explorer / ショートカットから起動 | コンソールの黒窓が付いてくる | 付かない（GUI サブシステム＋`AttachConsole`） |
| 開くディレクトリ | **常にホーム** | 起動したディレクトリ。`--cwd` でも指定できる |
| 分割・新タブのディレクトリ | 常にホーム | そのペインの現在地（OSC 7 を出すシェルのとき） |
| `-e <コマンド>` | 無い | ある。専用セッションで開くので既存に相乗りしない |
| `--help` / `--version` | 無い | ある |
| 透過・背景のぼかし | 無い | `--opacity` と DWM のアクリル（Windows 11） |
| 設定ファイル | 無い | `config.toml`（不透明度・ぼかし・文字サイズ） |

⚠️ 分割時のディレクトリ引き継ぎは **OSC 7 を出すシェルでのみ**効く。
`cmd.exe` は出さないのでホームで開く。PowerShell / bash はシェル統合を入れれば効く。

⚠️ ぼかしは Windows 11 22H2 以降の `DWMWA_SYSTEMBACKDROP_TYPE` を使う。
古い環境では属性が無視されるだけで、透過は残る。macOS / Linux は
コンポジタ側の仕事なので、ウィンドウを透過にするところまでしかやっていない。

## 5. 実機で確かめて、そこで見つけたもの

スクリーンショットを撮り、合成キー・合成マウスで GUI を操作して確かめた
（`--send` / `--tap` はそのために足した RPC の口）。
**画面を見なければ全部見逃していた**類のものが 4 件出た。

### 1. 色がすべて白茶けていた（sRGB とリニアの取り違え）

背景が `#0F1217` のはずが **`#454B54`** で出ていた。これは `0.06` を
sRGB→リニアに通した値とビット単位で一致する。サーフェスが sRGB フォーマットなので
GPU が書き込み時にリニア→sRGB を行うのに、こちらが sRGB の値をそのまま渡していた。

色は人が読める sRGB で書き続けたいので、**変換はシェーダの 1 箇所**（`to_linear`）で吸収する。
クリア色だけは頂点を通らないので CPU 側にも同じ式を置いた（`srgb_to_linear`）。
片方だけ直すと、文字が載っている領域と載っていない領域で背景色が食い違う。

### 2. 緑のガターマーカーだけが出ていなかった

`❯`（U+276F）が Consolas / MS Gothic / Segoe UI Emoji のどれにも無く、
失敗の `✖` だけが描かれていた。**字が出るかどうかに製品の見た目を賭けない**方針にして、
矩形で描くよう変えた。太さでも区別する（成功=細い / 実行中=中 / 失敗=太い）ので、
色が見分けにくくても伝わる。

### 3. `ac` が次のプロンプトまで飲んでいた

ガターをクリックしてヤンクしたら、次のコマンドのプロンプト行まで入っていた。
OSC 133 の `D` は出力を書き終えた**次の行頭**で来るため、それを終端に使うと 1 行はみ出す。
**次のブロックのプロンプト行の手前で頭打ち**にした。

### 4. ウィンドウをリサイズすると画面が崩れた 🔴

リサイズ後に打った文字が、プロンプトの無い空行の途中に浮いた。
`--tap` で生バイトを見たら答えが出た:

```
[pane 1] === RESIZED 108x30 ===
[pane 1] <ESC>[7;16Hecho TWO<ESC>[7;24H
```

ConPTY は**絶対座標**でエコーを打つ。つまり行数が減ったとき
「どちらの端で吸収するか」がホストと一致していないと、以降の座標が全部ずれる。
`Grid::resize` は上端から捨てていたが、ConPTY は**カーソルより下の空行から捨てる**。
逆に広げるときは履歴から引き戻す。両方直した。

これは**リサイズするすべてのユーザーが踏む**もので、
ヘッドレステストでは「行数が合っている」ことしか見ておらず素通りしていた。

### 5. ステータス行の左端はクリックできない

パレットの常設ボタンを左端に置いたが、合成クリックが届かなかった。
**ウィンドウのリサイズ枠（左下の角）に食われていた**。
ボタンを 1 桁内側に描き、判定範囲を左右に広げた。
角に置いた小さな標的は OS に取られる、という一般則。
