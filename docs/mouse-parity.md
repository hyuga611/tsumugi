# mouse-parity — 各操作のマウス等価と、それを腐らせない仕組み

「マウスでも一応できる」は数ヶ月で嘘になる。キーボード側に機能を足したとき、
マウス側を更新し忘れるからだ。**このドキュメントの本体は対応表ではなく、
対応表が自動的に正しくあり続ける仕組み（§2）である。**

---

## 1. 原則

### 1.1 等価とは「到達可能性の等価」であって「打鍵数の等価」ではない

`d3]e`（3つ先のエラーまで削除）をマウス3クリックで打てる必要はない。
求めるのは次の一点だけ:

> **すべてのコマンドは、マウスだけで 2 アクション以内に到達できる。**

キーボードが速い操作はキーボードが速いままでよい。禁じるのは
**「マウスからは絶対に届かない機能がある」状態**である。

### 1.2 マウスは「範囲を作る道具」、キーボードは「範囲に何かする道具」

vim の `operator + motion` は、マウスでは自然に **`選択 → 動詞`** の順になる。
tsumugi は両方の順序を許す:

| 順序 | 例 |
|---|---|
| 動詞が先（キーボード的） | `y` `i` `c` -> ヤンク |
| 範囲が先（マウス的） | ドラッグで選択 -> 右クリック -> ヤンク |

内部的には同じ `Command::Yank { range }` に落ちる。この合流点が §2 の基盤。

### 1.3 マウス操作は必ずモードを表示に反映する

ドラッグで範囲を取ったら、モード表示は `-- 選択 --` に変わる。
「マウスで操作するとモードレスになる」ことを許さない。マウス派も**モードを見て学ぶ**。
これが、マウスから入った人が自然にキーボードへ移行できる唯一の設計。

## 2. 等価を保証する構造

### 2.1 単一コマンドバス

```
  キーボード ─┐
  マウス   ─┤
  右クリックメニュー ─┼──> Command (enum) ──> Dispatcher ──> State
  コマンドパレット ─┤
  RPC (tsg-mux socket) ─┘
```

入力フロントエンドは**状態を直接触らない**。全員が `Command` を発行し、
唯一の `Dispatcher` がそれを適用する。右クリックメニューの項目もパレットの項目も、
**コマンドレジストリから生成される**ので、定義の二重管理が発生しない。

### 2.2 パリティテスト（CI で落とす）

```rust
// crates/tsg-modal/tests/parity.rs
#[test]
fn every_command_is_mouse_reachable() {
    for cmd in CommandRegistry::all() {
        assert!(
            cmd.mouse_path().is_some() || cmd.keyboard_only_reason().is_some(),
            "{} はマウスから到達できず、除外理由も宣言されていません", cmd.id()
        );
    }
}

#[test]
fn every_command_is_keyboard_reachable() {
    for cmd in CommandRegistry::all() {
        assert!(cmd.default_keymap().is_some() || cmd.in_palette(),
            "{} はキーボードから到達できません", cmd.id());
    }
}
```

新しいコマンドを足した開発者は、**マウス経路を書くか、書かない理由を宣言するかを強制される**。
「うっかり忘れる」を型と CI で潰す。これが本ドキュメントで最も重要な一節。

`mouse_path()` の実体は以下のいずれか:

| 種別 | 意味 |
|---|---|
| `Direct(gesture)` | 専用のジェスチャがある（クリック、ドラッグ等） |
| `Menu(section)` | 右クリックメニューの該当セクションに出る |
| `Palette` | コマンドパレット経由（＝2アクション: 右クリック -> パレット -> 選択、または常設ボタン1クリック -> 選択） |

`Palette` が最終保証。ここに落ちれば必ず 2 アクション以内に届く。

## 4. 対応表

### 4.1 モード遷移

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| Normal へ | `Esc` / `C-\` | スクロールバック上を左クリック / ホイールで上へスクロール | Direct |
| Insert へ復帰 | `i` | 末尾プロンプト行をクリック / ステータス行の「入力」バッジをクリック | Direct |
| Visual | `v` | 左ドラッグ | Direct |
| Visual Line | `V` | トリプルクリック | Direct |
| Visual Block | `C-v` | Alt＋ドラッグ | Direct |
| Command モード | `:` | ステータス行の `:` をクリック | Direct |
| Search | `/` | ステータス行の虫眼鏡をクリック | Direct |
| Layout モード | `Space` | ペインヘッダのグリップをクリック | Direct |

### 4.2 モーション（＝カーソル移動）

マウスにおいて、モーションは基本的に**すべてクリック1回**に潰れる。
ただし「意味を持った移動」（プロンプト間・エラー間）は視覚要素を用意する。

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| 任意位置へ | `hjkl` `w` `b` `f{c}` … | クリック | Direct |
| 前 / 次のプロンプト | `[[` `]]` | **左ガター**のプロンプトマーカー（`❯`）をクリック / ミニマップのマーカーをクリック | Direct |
| 前 / 次のエラー | `[e` `]e` | 左ガターの赤マーカーをクリック / ステータス行の「エラー 3件」をクリックしてリスト表示 | Direct |
| 前 / 次のパス・URL | `[p` `]p` `[u` `]u` | 直接ホバーしてクリック | Direct |
| 生きた末尾へ | `gp` / `G` | 右下の「最新へ」ボタン（スクロール中のみ出現） | Direct |
| マークへ | `` `{a} `` | ガターのマーク印をクリック | Direct |

**左ガターは、ターミナル固有モーションのマウス版そのもの**である。
OSC 133 で得た構造（プロンプト位置・終了コード）を可視化することで、
`[[` `]]` `[e` `]e` に対応するクリック標的が自動的に生まれる。ここは実装優先度が高い。

### 4.3 テキストオブジェクト（＝範囲の生成）

| オブジェクト | キーボード | マウス | 経路種別 |
|---|---|---|---|
| 単語 `iw` | `viw` | ダブルクリック | Direct |
| 行 | `V` | トリプルクリック | Direct |
| 引用符・括弧 `i"` `i(` | `vi"` `vi(` | 引用符 / 括弧の**上**をダブルクリック（対応範囲を選択） | Direct |
| コマンドブロック `ac` | `vac` | ガターのプロンプトマーカーをクリック（ブロック全体が選択される） | Direct |
| 出力ブロック `io` | `vio` | ガターのプロンプトマーカーを**ダブル**クリック | Direct |
| ファイルパス `if` | `vif` | パス上でダブルクリック（パス全体を1語として扱う） | Direct |
| URL `iu` | `viu` | URL 上でダブルクリック | Direct |
| ハッシュ `ih` | `vih` | SHA 上でダブルクリック | Direct |
| エラーブロック `ae` | `vae` | ガターの赤マーカーをクリック | Direct |
| 数値 `in` | `vin` | 数値上でダブルクリック | Direct |

**ダブルクリックの「単語」定義をコンテキスト依存にする**のが要点。
`src/main.rs:42` の上でのダブルクリックは `src` ではなく `src/main.rs:42` を取る。
これだけでターミナルのマウス体験が既存製品と決定的に変わる。

### 4.4 オペレータ（＝範囲に対する動詞）

範囲が選択されている状態で右クリック -> メニューから動詞を選ぶ（2アクション）。
高頻度のものは Direct 経路を別に用意する。

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| ヤンク | `y` | 選択 -> 右クリック -> 「コピー」 / 選択解除時に自動コピー（設定） | Menu |
| 削除 | `d` | 選択 -> 右クリック -> 「表示から削除」 | Menu |
| 変更 | `c` | 選択 -> 右クリック -> 「置き換え」 | Menu |
| **プロンプトへ送る** `!` | `!` | 選択 -> **右ドラッグでプロンプト行へドロップ** / 右クリック -> 「プロンプトへ送る」 | Direct + Menu |
| **即実行** `!!` | `!!` | 右クリック -> 「実行」（確認ダイアログ） | Menu |
| **パイプ** `>` | `>` | 選択 -> 右クリック -> 「…に通す」 -> コマンド入力 | Menu |
| 整形 `=` | `=` | 右クリック -> 「整形」 | Menu |
| 開く | `gx` / `C-]` | Ctrl＋クリック | Direct |

`!` の**ドラッグ＆ドロップ**は、マウス派にとってこの製品の看板機能になる。
ログの中のパスを掴んでプロンプトに落とす、という操作がキーボードの `!if` と完全に等価。

### 4.5 Layout（多重化）

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| 分割 | `Space s` / `Space v` | ペインヘッダの分割ボタン / ペイン端へのタブドロップ | Direct |
| ペイン移動 | `Space hjkl` | ペインをクリック | Direct |
| ペイン入れ替え | `Space HJKL` | 右クリック -> 「ペインを入れ替える」 | Menu |
| リサイズ | `Space <>+-` | 境界をドラッグ | Direct |
| 均等化 | `Space =` | 境界をダブルクリック | Direct |
| ズーム | `Space z` | 右クリック -> 「画面いっぱいに」 | Menu |
| 閉じる | `Space x` | 右クリック -> 「ペインを閉じる」 | Menu |

⚠️ 当初はペインヘッダ（掴む・×・ダブルクリック）を前提にしていたが、**ヘッダは作らなかった**。
1 ペインにつき 1 行を常時使う代償が、得られる操作に見合わない。
掴む対象が要る操作（入れ替え・ズーム）はメニュー経路に落とし、ヘッダ無しで
2 アクション以内を保っている（§1.1 の約束はこれで満たされる）。
境界のダブルクリックだけは掴む対象が既にあるので Direct のまま。
| タブ切替 | `Space n/p` `Space 1-9` | タブバーをクリック | Direct |
| タブ並べ替え | `Space [` `Space ]` | タブをドラッグ | Direct |
| 新規タブ | `Space c` | タブバーの `+` | Direct |
| **デタッチ** | `Space d` | タブバー右端のセッションバッジをクリック -> 「デタッチ」 | Menu |
| **アタッチ** | `Space S` | 右クリック -> 「セッションの一覧」 | Menu |
| ペイン検索 | `Space f` | セッションバッジをクリック -> 「ペインを探す」 | Menu |
| **タブを閉じる** | `Space X` | タブ末尾の `✕` | Direct |
| **作業台を組む** | `Space w` / シェルで `go` | 右クリック -> 「配置」-> 「作業台を組む」 | Menu |

`✕` の当たり判定は、見えている字より **1 桁広い**（`on_tab_close`）。
端の 1 桁は指が滑る場所で、そこを外すと「押したのに閉じない」になる。
描くときと当てるときで同じ関数を通すので、字幅を変えても
「見えているのに押せない」が生まれない。

### 4.5b 木（左のディレクトリ）

木は `Buffer` なので、**§4.2 のモーションも §4.4 のオペレータも
そのまま効く**。ここに並ぶのは、木の中でだけ意味を持つものだけ。

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| 開く / 畳む | 木の中で `Enter` `o` | 行をダブルクリック | Direct |
| 枝を開く / 畳む | 木の中で `l` / `h` | 行をダブルクリック | Direct |
| 新しいファイル / フォルダ | 木の中で `a` / `A` | 右クリック -> 「ファイル」 | Menu |
| 名前を変える | 木の中で `r` | 右クリック -> 「ファイル」 | Menu |
| 動かす | — | **ドラッグ＆ドロップ** | Direct |
| 読み直す | 木の中で `R` | 右クリック -> 「ファイル」 | Menu |

⚠️ **これらは既定のキーマップに入れていない。** `a` や `r` を全体で奪うと、
端末でもファイルでも意味が変わる。木の中でだけ拾う（`explorer_key`）ので、
「同じ字が、いま見ているものに応じていちばん近いものを指す」の一例になっている。
レジストリには載っているので、パレットと右クリックメニューからは
どこに居ても届く（§1.1 の到達可能性はそれで満たされる）。

**動かす道はマウスにしか無い。** キーボードで「切って貼る」を作ると、
切った状態を持ち歩くことになり、貼る前に木が変わったときの扱いが増える。
掴んだまま離す場所を見ているマウスなら、その状態は指の中にあって画面に無い。

**消す道はどちらにも無い。** 取り消せない操作を、指が滑る場所へ置かない。


### 4.5c 絵をプロンプトへ渡す

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| 貼り付け（絵） | `Ctrl＋Shift＋V` / `p` | **画像をウィンドウへ落とす** | Direct |

⚠️ **新しいコマンドは足していない。** 「貼り付け」は 1 つの動詞で、
クリップボードに入っているものに応じていちばん近いことをする
（字なら字、絵ならファイルにしてそのパス）。動詞を 2 つに割ると、
押す前に中身を知っている必要が出る。

置くところまでで、**Enter は押さない**（`gx` や右ドラッグと同じ作法）。

### 4.6 レジスタ・マーク・マクロ

| コマンド | キーボード | マウス | 経路種別 |
|---|---|---|---|
| レジスタ指定ヤンク | `"ay` | 選択 -> 右クリック -> 「コピー先」-> レジスタ一覧 | Menu |
| レジスタ一覧 / 貼付 | `:reg` / `"ap` | ステータス行のレジスタバッジをクリック -> クリックで貼付 | Direct |
| マーク設定 | `ma` | ガターを右クリック -> 「マーク」 | Menu |
| マクロ記録 | `qa` … `q` | ステータス行の録画ボタン | Direct |
| マクロ再生 | `@a` | 録画バッジをクリック -> 再生 | Direct |

### 4.7 コマンドパレット（最終保証）

- キーボード: `:cmd` または `C-S-p`
- マウス: **ステータス行左端の常設ボタン 1 クリック**

パレットは `CommandRegistry` を全走査して出す。検索可能で、各項目に既定キーバインドを併記する。
「マウスから始めた人がキーボードを覚える導線」も兼ねる。
これがある限り、パリティテストの `Palette` 経路は常に成立する。

## 5. alt-screen 時のマウス委譲

`concept.md` の所有権モデルの、マウス側の詳細。

| 子プロセスの状態 | ホイール | クリック / ドラッグ | 右クリック |
|---|---|---|---|
| primary、マウスレポート無効 | tsumugi がスクロール | tsumugi | tsumugi のメニュー |
| primary、マウスレポート有効（稀。fzf の inline モード等） | tsumugi がスクロール | **tsumugi**（primary は常にドキュメント） | tsumugi のメニュー |
| alt、マウスレポート無効（`less` 等） | tsumugi が**矢印キーに変換して送出**（慣例に合わせる） | tsumugi | tsumugi のメニュー |
| **alt、マウスレポート有効**（htop, lazygit, k9s） | **子プロセスへ SGR 1006 で送出** | **子プロセスへ送出** | **子プロセスへ送出** |
| 上記で `C-\` を押した後 | tsumugi | tsumugi | tsumugi のメニュー |

最終行が逃げ道。`C-\` で強制的に Normal に入れば、htop の画面もドキュメントとして掴める。
所有権が子プロセスにある間、ステータス行のマウスバッジは `🖱子` を表示し続ける。

### ステータス行のバッジは「クリックできる説明」にする

`🖱子` バッジ自体をクリックすると所有権が tsumugi に切り替わる（＝`C-\` と等価）。
これも Direct 経路として登録し、パリティテストを通す。

## 6. キーボード専用を許すもの（除外リスト）

`keyboard_only_reason()` を宣言してよいのは以下の型のみ。**それ以外の追加は PR でレビューする。**

| コマンド | 理由 |
|---|---|
| `.`（繰り返し） | 直前操作の再適用であり、マウスでは「同じ操作をもう一度する」が自然な等価。専用 UI を出すと混乱を増やす |
| `{count}` 前置 | マウスではドラッグ範囲そのものが量を表す。数値入力の UI を出す価値がない |
| `f{c}` / `t{c}` | 移動先をクリックすれば済む。純粋な速記であり、機能の追加ではない |
| `;` `,` | 同上 |

**除外できないもの（＝必ずマウス経路が要るもの）の例**: モード遷移、全オペレータ、
すべてのテキストオブジェクト、全 Layout 操作、レジスタ、マーク、セッション操作。

## 7. 実装状況（2026-08-24）

パリティテストが見ているのは「マウス経路が**宣言**されているか」であり、
**実配線があるかは見ていない**。両者を混ぜると「テストは通るのにマウスで届かない」が
生まれるので、現状をここに書く。

**配線済み** — §3 のクリック / ダブル・トリプルクリック / ドラッグ / Alt＋ドラッグ /
ホイール / 中クリック / 右クリック、§4.2 の任意位置へ、§4.3 の単語・引用符・括弧・
パス・URL・ハッシュ・数値（すべてダブルクリック）とガターのプロンプトマーカー、
§4.5 のペイン移動・リサイズ・タブ切替、§5 の委譲全行、ステータス行のマウスバッジ、
**§4.4 の `Menu` 経路（右クリックメニュー）と §4.7 の `Palette` 経路（常設ボタン）**、
§4.6 のマーク（ガターの英字をクリック）とマクロ（ステータス行の記録 / 再生バッジ）、
§4.5 のペイン入れ替え・ズーム・均等化（境界のダブルクリック）・タブ並べ替え（タブのドラッグ）・
セッション一覧、**§3 の Ctrl＋ホイール（字の大きさ）・ホバーの下線・Ctrl＋クリックで開く・
右ドラッグ＆ドロップ**。

これで §3 のポインタ語彙と §4 の対応表は全行が実配線になった。

メニューとパレットの項目は**レジストリから生成する**ので、コマンドを足した時点で
両方に出る。選んだ項目は `Engine::invoke(id)` を通ってキーボードと同じ `Command` に
落ちる。メニュー専用の副作用は 1 つも無い。

**未配線** — 無し。

ホバーの下線と Ctrl＋クリックは**同じ判定（`open_kind`）だけ**を見る。
別々に持つと「下線は出るのに開かない」「下線が無いのに開ける」が生まれる。
判定は形のはっきりしたもの（URL・パス・7 桁以上の 16 進）に限る。ここを甘くすると
**画面じゅうの語に下線が出て読めなくなる**。

右ドラッグは**離した場所**で意味が決まる。同じセルで離せばただの右クリック
（メニュー）、動かして離せばプロンプトへ落とす。押した瞬間にメニューを出すと
ドラッグの余地が無くなるので、メニューは離すまで出さない。

ガターは 2 桁で、左がコマンドブロックの色バー、右が印の英字。**同じ行に両方あっても
別々に押せる**ようにこう分けた（1 桁に重ねると、印を置いた行だけブロックが選べなくなる）。

ステータス行の常設ボタンは、描画とヒット判定を同じ列の並びから作る（`status_hit`）。
別々に持つと字幅を変えた瞬間に「見えているのに押せない」が生まれる。

詳細は [`m3-results.md`](m3-results.md) §4。
