# modal-spec — モード遷移とキーマップ全表

前提: `concept.md` の中心命題「グリッドはドキュメントである」と、alt-screen による所有権規則。

---

## 1. バッファ種別

モーダル操作の対象は3種類。**同じ `Buffer` トレイトを実装する**（`arch.md` 参照）ため、
モーションとテキストオブジェクトは全種で共通。差が出るのは**オペレータの可否**だけ。

| 種別 | 実体 | 追記者 | 書き換え |
|---|---|---|---|
| `Term(primary)` | スクロールバック＋現在画面を通した連続ドキュメント | 子プロセス（末尾に追記） | ローカル可（後述） |
| `Term(alt)` | 代替画面。履歴を持たない | 子プロセス（全面書き換え） | 不可（読み取り専用） |
| `File` | ファイルバッファ（内蔵エディタ） | なし | 可 |

`Term(primary)` の「ローカル書き換え」とは、**画面上の表示を編集すること**を指す。
子プロセスには何も送らない。ノイズ行を消す・整形して残す、といったログ整理のための操作。
実プロセスへ送るのは `!` オペレータだけが行う。

## 2. モード一覧

| モード | 表示 | 役割 |
|---|---|---|
| **Insert** | `-- 入力 --` | キーはそのまま PTY へ。既存ターミナルと完全に同じ状態。**既定** |
| **Normal** | `-- 通常 --` | グリッドをドキュメントとして操作。モーション・オペレータ |
| **Visual** | `-- 選択 --` / `-- 選択(行) --` / `-- 選択(矩形) --` | 範囲選択。char / line / block |
| **Operator-pending** | `-- 待機 --` | オペレータ入力後、モーション or テキストオブジェクト待ち |
| **Command** | `:` | ex コマンドライン |
| **Search** | `/` `?` | 検索入力 |
| **Layout** | `-- 配置 --` | ペイン・タブ・セッションの操作に専念する持続モード |

`Layout` を prefix キー（tmux 方式）ではなく**モード**にしたのは、
連続操作（分割 → 移動 → リサイズ → リサイズ）で prefix を毎回打つ苦痛を消すため。
一発だけ打ちたい場合のために `C-w {key}` を one-shot エイリアスとして残す。

## 3. 遷移図

```
                       +--------------------------------------+
                       |              Insert                  |  <- 起動時
                       |  (キーは PTY へ / 既定)               |
                       +---+------------------------------^---+
              Esc (primary)|                              | i I a A o O
                    C-\ (常時)                            | (Term では末尾へ復帰)
                       +---v------------------------------+---+
        +---- v V C-v -+              Normal                  +- : --> Command -+
        |              |  (モーション / オペレータ / ジャンプ)  |                 |
        |        +-----+                                      +- / ? -> Search -+
        |        |     +---+-----------------------------^----+                 |
        |   y d c ! > =    | C-w{key} = one-shot          |                      |
        |        |      Space (or C-w w)                  |  Esc / 実行          |
        |   +----v-----+   |                              +----------------------+
        |   | Operator |   |
        |   | -pending |---+  motion|textobject で確定 -> Normal
        |   +----^-----+
        |        | y d c ! > = (選択に対して即適用)
    +---v--------+---+                    +------------------+
    |     Visual     |                    |      Layout      |
    | char/line/block|                    | 分割・移動・リサイズ |
    +----------------+                    | タブ・セッション    |
         Esc -> Normal                    +------------------+
                                            Esc / Enter -> Normal
```

### 所有権による Esc の分岐（最重要）

| ペインの状態 | `Esc` | `C-\` |
|---|---|---|
| `Term(primary)` = シェルのプロンプト | **Normal へ** | Normal へ |
| `Term(alt)` = 全画面 TUI 実行中 | **子プロセスへ送出**（tsumugi は反応しない） | **Normal へ（強制奪取）** |
| `File` = 内蔵エディタ | **Normal へ** | Normal へ |

`:pin mouse self|app` / `:pin key self|app` でペイン単位に固定できる。
ステータス行に所有権インジケータ（`⌨自` / `⌨子`、`🖱自` / `🖱子`）を**常時**表示する。
「今どっちが持っているか分からない」状態を作らないことがこのモデルの生命線。

### Insert への復帰位置

`Term` バッファで Normal から `i` を押したとき、カーソルはスクロールバック上の任意位置にありうる。
**入力は常に「生きている末尾」へ行く**ため、`i` は暗黙にカーソルを末尾のプロンプト行へ戻す。
`i` `a` `I` `A` `o` `O` はすべて Term バッファでは同義（＝末尾へ復帰して Insert）。
`File` バッファでは vim 通りに区別する。

## 4. 文法

```
[count] operator [count] {motion | text-object}
[count] {motion}
["reg] operator ...
```

vim と同じ。合成規則を守ることで、モーション1個・オブジェクト1個を足すたびに機能が掛け算で増える。
**単発コマンドを増やす前に、必ず「これは既存の文法で表せないか」を問う。**

## 5. モーション

### 5.1 汎用（全バッファ種別で共通）

| キー | 動作 |
|---|---|
| `h` `j` `k` `l` | 左 / 下 / 上 / 右 |
| `w` `W` `b` `B` `e` `E` `ge` | 単語単位 |
| `0` `^` `$` | 行頭 / 最初の非空白 / 行末 |
| `gg` `G` | ドキュメント先頭 / 末尾（Term ではスクロールバック最上端 / 現在行） |
| `{` `}` | 空行区切りの段落 |
| `f{c}` `F{c}` `t{c}` `T{c}` `;` `,` | 行内文字検索 |
| `%` | 対応括弧へ |
| `H` `M` `L` | 画面上 / 中 / 下 |
| `C-d` `C-u` `C-f` `C-b` | 半画面 / 全画面スクロール |
| `` `{mark} `` / `'{mark}` | マークへ |
| `n` `N` | 検索結果の次 / 前 |
| `*` `#` | カーソル下の語を前方 / 後方検索 |

### 5.2 ターミナル固有 — OSC 133 依存

シェル統合（OSC 133 セマンティックプロンプトマーク）が入っている場合に有効化される。
**これが tsumugi の語彙の中核**であり、`arch.md` の必須依存として扱う。
シェル統合が無い場合はヒューリスティック（プロンプト文字列パターン）にフォールバックし、
ステータス行に劣化表示を出す。

| キー | 動作 |
|---|---|
| `[[` / `]]` | 前 / 次の**プロンプト行**へ（＝コマンド境界を飛ぶ） |
| `[o` / `]o` | 前 / 次の**コマンド出力ブロック**の先頭へ |
| `[e` / `]e` | 前 / 次の**非ゼロ終了コマンド**へ（終了コードは `OSC 133;D` から取得） |
| `[p` / `]p` | 前 / 次のパスらしき文字列へ |
| `[u` / `]u` | 前 / 次の URL へ |
| `gp` | 現在の生きているプロンプト（＝末尾）へ |

`]e` は実利が大きい。長いビルドログの中でこけたコマンドだけを渡り歩ける。

## 6. テキストオブジェクト

### 6.1 汎用

| オブジェクト | 内容 |
|---|---|
| `iw` `aw` `iW` `aW` | 単語 |
| `i"` `a"` `i'` `a'` `` i` `` `` a` `` | 引用符 |
| `i(` `a(` `i[` `a[` `i{` `a{` `i<` `a<` | 括弧 |
| `ip` `ap` | 段落 |
| `is` `as` | 文 |

### 6.2 ターミナル固有

| オブジェクト | 内容 | 用途 |
|---|---|---|
| `ic` / `ac` | **コマンドブロック** — `ic` は入力されたコマンド行のみ、`ac` はプロンプト＋コマンド＋出力の全体 | `yac` で「この実行まるごと」をコピーして issue に貼る |
| `io` / `ao` | **出力ブロック** — `io` は出力本体、`ao` は末尾の空行含む | `yio` で出力だけコピー |
| `if` / `af` | **ファイルパス** — `if` はパスのみ、`af` は行番号・列番号サフィックス込み（`src/main.rs:42:8`） | `!if` でそのファイルを次のコマンドへ渡す |
| `iu` / `au` | **URL** — `iu` は URL、`au` は囲む括弧等を含む | `gx` で開く、`yiu` でコピー |
| `ih` / `ah` | **ハッシュ / ID** — git SHA・コンテナ ID・UUID らしき連続列 | `!ih` でそのまま次のコマンドへ |
| `in` / `an` | **数値** — `an` は単位を含む（`1.2GB`, `300ms`） | |
| `ie` / `ae` | **エラーブロック** — バックトレース / スタックトレースらしき連続範囲 | `yae` でまるごと共有 |

`if` / `af` は vim の「関数」オブジェクトと衝突する。`File` バッファでは `if` = 関数、
`Term` バッファでは `if` = ファイルパスとする。**バッファ種別でオブジェクト表が切り替わる**のは
意図的な設計（同じキーが常に「そのバッファで最も意味のあるもの」を指す）。→ 未決事項に記載。

## 7. オペレータ

| キー | 動作 | `Term(primary)` | `Term(alt)` | `File` |
|---|---|:---:|:---:|:---:|
| `y` | ヤンク（レジスタへ） | 可 | 可 | 可 |
| `d` | 削除（表示から消す。プロセスには無関係） | 可 | 不可 | 可 |
| `c` | 削除して Insert | 不可 | 不可 | 可 |
| `!` | **範囲をシェルの入力へ送る** | 可 | 可 | 可 |
| `>` | **範囲を外部コマンドへパイプし、結果を新ペインに開く** | 可 | 可 | 可 |
| `=` | 整形（JSON / YAML / テーブル整列を自動判定） | 可 | 不可 | 可 |
| `gu` `gU` `g~` | 大文字小文字 | 不可 | 不可 | 可 |
| `gc` | コメントトグル | 不可 | 不可 | 可 |

### `!` オペレータ — ターミナル固有の主役

範囲のテキストを**現在のプロンプトへ挿入**する（実行はしない。Enter はユーザーが押す）。

```
!if     カーソル下のファイルパスをプロンプトへ  ->  $ src/main.rs
!ih     git SHA をプロンプトへ                ->  $ 3f9a2c1
!ac     直前のコマンドを丸ごと再投入            ->  $ cargo build --release
```

修飾:

- `!!{motion}` — 挿入ではなく**即実行**する（Enter 込み）。破壊的なので確認プロンプトを既定で出す。
- `!{motion}` の直後にコマンドを打つとテンプレート展開する（`{}` が範囲に置換される）。
  例: `!if` して `code {}` -> `$ code src/main.rs`

### `>` オペレータ — パイプ

```
>ao jq .                   出力ブロックを jq に通した結果を新ペインで開く
>ae rustc --explain E0308
>ip sort -u
```

結果ペインは `File` バッファ相当（＝そのまま vim 操作でき、保存もできる）。

| 機能 | キー | 備考 |
|---|---|---|
| レジスタ指定 | `"{a-z}` / `"{A-Z}`（追記） | |
| 無名 / ヤンク | `""` `"0` | |

| ジャンプリスト | `C-o` `C-i` | ペインをまたいで記録する |

## 9. Layout モード（多重化）

`Space`（または `C-w w`）で入る。持続する。`Esc` で抜ける。

| キー | 動作 |
|---|---|
| `s` / `v` | 水平分割 / 垂直分割 |
| `h` `j` `k` `l` | ペイン移動 |
| `H` `J` `K` `L` | ペインを移動（入れ替え） |
| `<` `>` `+` `-` | リサイズ（count 対応: `10>`） |
| `=` | 均等化 |
| `z` | 現在ペインをズーム（トグル） |
| `x` | ペインを閉じる（確認あり） |
| `n` / `p` | 次 / 前のタブ |
| `c` | 新規タブ |
| `1`–`9` | タブ直接指定 |
| `t` | タブ一覧をピッカーで表示 |
| `d` | **セッションからデタッチ**（プロセスは生き続ける） |
| `S` | セッション一覧 / アタッチ |
| `f` | ペインをピッカーで検索（コマンド名・cwd で絞る） |
| `e` | 現在ペインを `File` バッファ（内蔵エディタ）に切り替える |

one-shot 版: `C-w s`, `C-w v`, `C-w h` … は Layout モードに入らず1回だけ実行。

## 10. Command モード（`:`）

| コマンド | 動作 |
|---|---|
| `:e {path}` `:w` `:wq` `:q` | 内蔵エディタのファイル操作 |
| `:sp` `:vs` `:tabnew` | 分割・タブ |
| `:new {cmd}` | コマンドを走らせる新ペイン |
| `:s/{pat}/{rep}/[g]` | 置換（Term バッファでも表示に対して有効） |
| `:g/{pat}/{cmd}` | グローバルコマンド。`:g/WARN/d` でログのノイズ一括除去 |
| `:v/{pat}/d` | 逆マッチ削除（`:v/ERROR/d` で該当行だけ残す） |
| `:sort [u] [n]` | ソート |
| `:pin mouse self\|app` / `:pin key self\|app` | 所有権の固定 |
| `:set {option}` | 設定の一時変更 |
| `:map` `:nmap` `:vmap` | キーマップ変更 |
| `:reg` `:marks` `:jumps` | 一覧 |
| `:sessions` `:attach {name}` `:detach` | セッション |
| `:capture [file]` | 現在バッファをファイルへ書き出し |
| `:cmd {name}` | **コマンドパレット**（`mouse-parity.md` の最終保証） |

`:g` / `:v` はターミナルで異様に効く。`cargo build` の出力から警告だけ残す、
`docker logs` からノイズを消す、が1コマンドで終わる。

---

## 11. カウント・繰り返し

- `{count}` は vim 通り。`3]e` で3つ先のエラーへ。
- `.` は最後の**変更系**オペレータを繰り返す。`!` は変更系に含める
  （`.` で同じ抽出を次の行にも適用できる）。

## 12. 未決事項

1. `if` / `af` のバッファ依存切り替え（関数 vs ファイルパス）を許容するか、ターミナル側を
   `iF` などに逃がすか。**実際に両方使ってから決める**。
2. `d` を `Term(primary)` で許すと「消したログは戻らない」問題が出る。アンドゥ（`u` / `C-r`）を
   Term バッファにも持たせるか。→ 持たせる方向で検討（グリッドをドキュメントと定義した以上、
   アンドゥが無いのは命題と矛盾する）。
3. `Space` を Layout モードに使うと、内蔵エディタで leader として使えない。
   `File` バッファでは `Space` を leader、Layout は `C-w` のみ、とする案。
4. マクロ記録中に子プロセスへ送ったキーを再生対象に含めるか（含めると危険、含めないと不完全）。
5. `!!` の確認プロンプトの既定 on/off。
